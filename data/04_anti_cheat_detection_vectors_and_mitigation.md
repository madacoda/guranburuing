## 2. Client-Side Telemetry & Traps

### 2.1 The `isTrusted` DOM Flag
Modern browsers set the read-only boolean `event.isTrusted` to `true` exclusively when an event is generated by physical user interaction (hardware mouse, keyboard, or touchscreen).
- Calling `element.click()` or `element.dispatchEvent(new MouseEvent(...))` in JavaScript generates an event with `isTrusted === false`.
- Any automated system relying on in-page JavaScript dispatchers for critical interactions (such as the Attack button or CAPTCHA selection) can be flagged with a single line of client telemetry:
  ```javascript
  // Native honeypot pattern
  btn.addEventListener('click', (e) => {
    if (!e.isTrusted) {
      reportSuspiciousClient({ reason: 'synthetic_click', target: e.target.id });
    }
  });
  ```
- **Mitigation**: Automation must emit inputs via the **Chrome DevTools Protocol (CDP)** (`Input.dispatchMouseEvent`, `Input.dispatchTouchEvent`). CDP events are synthesized at the browser kernel level and execute with `isTrusted: true`.

### 2.2 Invisible Honeypot DOM Elements
Cygames embeds transparent overlay elements (`opacity: 0`, `pointer-events: auto`, zero z-index or off-screen coordinates) positioned directly adjacent to high-frequency buttons (e.g., Attack, Reload, Back, Summons).
- Simplistic bots using hardcoded pixel coordinates or aggressive bounding box offsets will clip these invisible honeypot layers.
- If an interaction event fires on a honeypot DOM node, the client immediately transmits a covert beacon to Cygames telemetry endpoints.
- **Mitigation**: Calculate precise bounding boxes using `Element.getBoundingClientRect()`, contract the bounding box inwards by 4–8 pixels (safe inner zone), and never blindly click screen-space coordinates without verifying DOM target hierarchy.

## 3. Mathematical Behavioral Modeling

Automated bots typically fail because their behavioral metrics exhibit near-zero variance. Cygames runs anomaly detection models (similar to isolation forests and PCA clustering) across user event streams.

### 3.1 Spatial Centroid Clustering ("Pixel Sniping")
Naive automation engines click the exact center of a button repeatedly:
$$(x, y) = \left( x_{min} + \frac{W}{2},\; y_{min} + \frac{H}{2} \right)$$
Across 500 raids, plotting these click locations yields a single point or a uniform rectangular distribution. Real human motor control exhibits a bivariate Gaussian distribution centered slightly off-center with natural hand-tremor variance.

#### Bivariate Gaussian Spatial Sampling Algorithm
To generate human-like click coordinates:

$$\begin{aligned}
x &= \mu_x + \sigma_x \cdot Z_1 \\
y &= \mu_y + \sigma_y \cdot Z_2
\end{aligned}$$

Where:
- $Z_1, Z_2 \sim \mathcal{N}(0, 1)$ via Box-Muller transform:
  $$Z_1 = \sqrt{-2 \ln U_1} \cos(2\pi U_2), \quad Z_2 = \sqrt{-2 \ln U_1} \sin(2\pi U_2)$$
- $\mu_x, \mu_y$: Bounding box center with a minor personal bias ($\pm 3\%$)
- $\sigma_x = \frac{\text{Width}}{6}, \quad \sigma_y = \frac{\text{Height}}{6}$ (ensuring 99.7% of clicks fall within the button boundaries)
- **Bounding Box Clamp**: Coordinates must be strictly clamped with an inward padding $\delta \ge 3\text{px}$:
  $$x_{clamped} = \max(x_{min} + \delta, \min(x_{max} - \delta, x))$$

### 3.2 Temporal Autocorrelation & Log-Normal Delays
Simple bots implement delays using `Math.random()` or uniform intervals:
$$T_{delay} = \text{Base} + \text{rand}(0, 500)$$
A uniform distribution has flat probability density, which is biophysically impossible for human neurology. Human reaction times and decision latencies follow a **Log-Normal distribution** with a long right tail (representing micro-distractions, blinking, or visual verification).

#### Log-Normal Latency Formulation
$$f(t; \mu, \sigma) = \frac{1}{t \sigma \sqrt{2\pi}} \exp\left( -\frac{(\ln t - \mu)^2}{2\sigma^2} \right), \quad t > 0$$

```typescript
function getHumanDelay(medianMs: number, sigma = 0.25): number {
  const mu = Math.log(medianMs);
  const u1 = Math.random();
  const u2 = Math.random();
  const z = Math.sqrt(-2.0 * Math.log(u1)) * Math.cos(2.0 * Math.PI * u2);
  return Math.max(50, Math.floor(Math.exp(mu + sigma * z)));
}
```

### 3.3 Motor Kinematics: Minimum-Jerk Spline Generation
When moving the cursor between buttons, humans do not move in straight linear paths (Bresenham's algorithm) or teleport instantaneously.

According to the **Flash & Hogan (1985) Minimum-Jerk Model**, human arm movements minimize the third derivative of position (jerk):

$$J = \frac{1}{2} \int_0^D \left( \left(\frac{d^3 x}{dt^3}\right)^2 + \left(\frac{d^3 y}{dt^3}\right)^2 \right) dt$$

The closed-form kinematic trajectory for moving from $(x_0, y_0)$ to $(x_f, y_f)$ over duration $D$ is given by:

$$x(\tau) = x_0 + (x_f - x_0)\left( 10\tau^3 - 15\tau^4 + 6\tau^5 \right)$$
$$y(\tau) = y_0 + (y_f - y_0)\left( 10\tau^3 - 15\tau^4 + 6\tau^5 \right)$$

Where $\tau = \frac{t}{D} \in [0, 1]$.
Adding a slight perpendicular sinusoidal arch simulates natural wrist curvature:

$$x_{final}(t) = x(\tau) + A \cdot \sin(\pi \tau) \cdot (-\sin \theta)$$
$$y_{final}(t) = y(\tau) + A \cdot \sin(\pi \tau) \cdot (\cos \theta)$$

Where $\theta = \operatorname{atan2}(y_f - y_0, x_f - x_0)$ and $A$ is the arc amplitude ($10\text{px} \le A \le 40\text{px}$).

## 4. Visual CAPTCHA Protocols & Fail-Safe Architecture

### 4.1 Trigger Conditions
Cygames deploys visual CAPTCHAs under the following conditions:
1. Continuous raiding exceeding 3.5 to 5 consecutive hours without session breaks.
2. Rapid AP/EP item consumption exceeding theoretical limits (> 400 EP/hour).
3. Repetitive anomalous network timing patterns.

### 4.2 Fail-Safe Protocol
When the DOM indicates a CAPTCHA modal (`.prt-popup-body .img-verify` or selector `#cnt-verification`):
1. **Immediate Execution Freeze**: Instantly pause all automated workflows.
2. **Audio / Push Notification**: Emit desktop alert or webhook to Telegram/Discord with a screenshot of the challenge.
3. **Zero Automated Guessing**: Never allow an unverified heuristic to guess the CAPTCHA image. A single incorrect CAPTCHA answer increases account suspicion tier by 500%; three consecutive failures trigger an automatic 24-hour ban or permanent ban.
4. **Manual Intervention Mode**: Await human solving or route the challenge to an authenticated solving subagent with 99.9% verified visual accuracy.
